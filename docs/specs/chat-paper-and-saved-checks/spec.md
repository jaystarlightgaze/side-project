# 대화창 디자인 통일과 할 일 체크 저장

예보관 대화창을 꼬마 명식표 종이 톤으로 맞추고, 오늘 할 일에 체크한 것이 같은 예보를 다시 볼 때 사라지지 않게 한다. 이미 배포된 기능의 마무리 작업이며, 대화와 예보의 동작은 바뀌지 않는다.

연결된 자료:
- [PRODUCT.md](../../../PRODUCT.md): "30초 안에 끝나는 가벼움", "나쁜 예보도 다독임으로 끝낸다", "재미로 보는 예보임을 밝힌다"를 따른다.
- [saju-chart-card spec](../saju-chart-card/spec.md): 카드와 폼의 시각 언어(종이 톤, 둥근 모양, 파스텔)와 할 일 체크 동작. 이 Spec은 그 "미룬 결정 체크 상태 저장"과 "예보관 대화창의 디자인"을 정한다.
- [step-pages-layout spec](../step-pages-layout/spec.md): 대화창의 자리와 `/today/chat` 배치. 이 Spec은 배치를 바꾸지 않고 대화창 안쪽 모양만 다룬다.
- [forecaster-chat-memory spec](../forecaster-chat-memory/spec.md): 대화 동작(답 받기, 먼저 묻는 질문, 권유). 그 동작은 그대로다.
- [ui-composition](../../decisions/ui-composition.md): component 선택과 token 사용은 이 계약을 따른다.

## 사용자에게 보이는 결과

1. `/today/chat`의 예보관 말풍선과 내 말풍선이 서로 다른 파스텔 색의 둥근 말풍선으로 구분된다. 입력칸과 "보내기" 버튼은 `/setup` 폼과 같은 둥근 모양과 글씨체다.
2. 답을 기다리는 동안 "예보관이 답을 쓰는 중…" 표시가 같은 종이 톤으로 보이고, 실패하면 같은 톤의 실패 안내가 나온다.
3. 오늘 할 일에 체크하고 페이지를 새로고침하거나 다른 페이지에 갔다 와도, 같은 예보가 보이는 동안은 체크가 그대로 남는다. 새 예보를 받으면 체크는 풀린 상태로 시작한다.

## 승인된 범위

- 대화창 안쪽(말풍선, 입력칸, 보내기 버튼, 준비 중과 실패 표시)의 시각 디자인
- 할 일 체크 상태를 이 브라우저에 저장하고 복원하기

## 수용 기준

배포 주소에서 실제 브라우저로 아래를 확인한다.

- AC1. `/today/chat`에서 예보관의 말과 내 말이 서로 다른 색의 둥근 말풍선으로 구분되어 보인다. 입력칸과 "보내기" 버튼은 `/setup` 폼의 입력칸과 같은 둥근 모양과 글씨체다. 375px 폭에서 가로 스크롤이 없고, 긴 답도 말풍선 안에서 줄바꿈된다.
- AC2. 답을 기다리는 동안 "예보관이 답을 쓰는 중…" 표시가 보이고 "보내기"는 누를 수 없다. 대화 요청이 실패하면 같은 종이 톤의 실패 안내와 다시 보내는 방법이 보인다.
- AC3. 대화 동작(질문 보내기, 답 받기, 예보관이 먼저 묻는 질문, 대화 권유 한 줄, 로그인 사용자의 저장과 복원)은 forecaster-chat-memory와 step-pages-layout의 수용 기준대로 계속 통과한다.
- AC4. 로그인한 상태에서 `/today`의 할 일 하나를 체크하고 페이지를 새로고침하면, 같은 카드에 그 체크가 남아 있고 "n/N 완료" 문구도 같다. `/today/chat`의 줄인 카드(읽기 전용)에도 같은 체크가 보인다.
- AC5. 새 예보를 받으면(`/today`의 "오늘 예보 받기", 또는 "명식 다시 세우기" 뒤 "예보 보기") 체크는 모두 풀린 상태로 시작한다. 로그인하지 않은 채 새로고침해서 "오늘 예보 받기" 버튼을 거쳐 다시 받은 카드도 마찬가지다.
- AC6. 저장된 체크는 날짜가 바뀌면 적용되지 않는다. 다른 브라우저에서 같은 계정으로 로그인하면 체크는 이어지지 않는다(이 브라우저에만 저장). 저장값이 깨져 있어도 오류 없이 모두 풀린 상태로 열린다.

## 정해진 제약과 이유

- **동작은 바꾸지 않는다:** 대화 응답, 먼저 묻는 질문, 권유 조건, 기억은 그대로다. 보이는 모양과 체크 저장만 바꾼다. 이미 확인된 수용 기준을 깨지 않기 위해서다.
- **체크는 이 브라우저에만 저장:** 서버나 계정에는 저장하지 않는다. 체크 한 번이 계정 데이터가 될 만큼 중요하지 않고, 새 DB 변경 없이 끝내기 위해서다. 같은 예보를 식별하는 방법은 구현에서 정한다.
- **줄인 카드의 체크는 읽기 전용 그대로:** `/today/chat`에서는 체크를 바꿀 수 없다. (step-pages-layout의 결정)
- **component와 token:** 말풍선은 직접 만들되 입력칸과 버튼은 shadcn 공식 component를 쓰고, 색은 기존 프로젝트 token(종이, 파스텔)을 쓴다. (`ui-composition`)
- **글씨체:** 폼과 카드가 쓰는 같은 글씨체(Gowun Dodum)를 쓴다.
- **언어:** 화면과 문구는 한국어다.

## 가정 (에이전트가 정한 기본값, 바꿔도 됨)

- 예보관 말풍선은 연한 노랑, 내 말풍선은 포인트색(진한 분홍 또는 초록) 계열이다. 정확한 색은 기존 token 중에서 고른다.
- 체크는 예보가 만들어진 날짜와 예보 자체(운 지수와 총평 등)로 같은 예보인지 판단한다. 같은 날 같은 입력으로 새로 받은 예보는 문구가 달라 다른 예보로 본다.
- 체크가 풀리는 시점은 새 예보를 받을 때와 날짜가 바뀔 때뿐이다.

## 범위 밖과 이유

- 대화창의 위치, 배치, 줄인 카드 모양: step-pages-layout의 결정이다.
- 체크 상태를 계정에 저장하거나 기록·통계로 쓰기: 30초 원칙상 지금은 필요 없다.
- 대화 기록 목록, 대화 내용 저장 방식 변경: forecaster-chat-memory의 몫이다.
- 보안 하드닝, 엣지케이스 방어: AGENTS.md 예산상 범위 밖이다.

## 미룬 결정

- **계정에 체크 저장:** 사용자가 "다른 기기에서도 체크가 이어지면 좋겠다"고 하면 다시 연다.

## 남은 위험

- 같은 예보를 식별하는 기준이 어긋나면 새로고침 뒤에 체크가 풀리거나, 반대로 다른 예보에 남을 수 있다. AC4와 AC5를 배포 주소에서 직접 확인해 막는다.
